    方法介绍-scheduleProcessStoppingAndFinishingActivitiesIfNeeded

    biubiubiu 2026/1/22 AMSActivity生命周期

    正常的逻辑在 ActivityTaskSupervisor::scheduleIdle 会发送 IDLE_NOW_MSG 消息，进而触发 ActivityTaskSupervisor::processStoppingAndFinishingActivities 来触发 Activity 的 onStop 或者 onDestroy 。

    但是之前试过将 ActivityThread::handleResumeActivity 方法下最后一行将 Idler 添加进 IdleHandler 的代码删了，也会触发 stop 。 触发逻辑是 发生了一个 “PROCESS_STOPPING_AND_FINISHING_MSG”消息，当时就没太在意。

    然后发现本地动画结束都都会有下面这个调用链，这里不同的条件会触发这2个消息的发送，引起了好奇。

    
LocalAnimationAdapter::startAnimation  -- 有个动画结束回调
    ......动画结束回调处理
        ActivityRecord::onAnimationFinished
            AppTransition::notifyAppTransitionFinishedLocked
                WindowManagerService::onAppTransitionFinishedLocked
                    ActivityRecord::updateReportedVisibilityLocked
                        ActivityRecord::onWindowsVisible
                            ActivityTaskSupervisor::scheduleProcessStoppingAndFinishingActivitiesIfNeeded
                                ActivityTaskSupervisor::scheduleIdle
                                    发送消息：IDLE_NOW_MSG
                                发送消息：PROCESS_STOPPING_AND_FINISHING_MSG

    具体方法代码如下：

    # ActivityTaskSupervisor
    void scheduleProcessStoppingAndFinishingActivitiesIfNeeded() {
        
        if (mStoppingActivities.isEmpty() && mFinishingActivities.isEmpty()) {
            return;
        }
        //  已经resume的Activity处于空闲状态，则开始调度
        if (mRootWindowContainer.allResumedActivitiesIdle()) {
            android.util.Log.d("biubiubiu", "ActivityTaskSupervisor  scheduleIdle: ");
            scheduleIdle();
            return;
        }
        if (!mHandler.hasMessages(PROCESS_STOPPING_AND_FINISHING_MSG)
                && mRootWindowContainer.allResumedActivitiesVisible()) {
            if (DEBUG_IDLE) Slog.d(TAG_IDLE, "sendEmptyMessage PROCESS_STOPPING_AND_FINISHING_MSG: Callers=" + Debug.getCallers(8));
            mHandler.sendEmptyMessage(PROCESS_STOPPING_AND_FINISHING_MSG);
        }
    }

    # 1.1 没有需要stop和finish的地方

    如果2个列表里都没有数据，则说明不需操作了

    # 1.2 所有的resume的Activity处于空闲状态

    在看 RootWindowContainer::allResumedActivitiesIdle 方法前，需要先了解一下什么是 ResumedActivity

    简单理解成：当前屏幕正在显示的 Activity 。

    如果想详细了解的话移步【XXXX】

    现在开始看 RootWindowContainer::allResumedActivitiesIdle

    # RootWindowContainer
    boolean allResumedActivitiesIdle() {
        // 从上往下遍历屏幕
        for (int displayNdx = getChildCount() - 1; displayNdx >= 0; --displayNdx) {
            // TODO(b/117135575): Check resumed activities on all visible root tasks.
            final DisplayContent display = getChildAt(displayNdx);
            // 重点* 1. 屏幕如果处理休眠状态则跳过
            if (display.isSleeping()) {
                // No resumed activities while display is sleeping.
                continue;
            }

            // If the focused root task is not null or not empty, there should have some activities
            // resuming or resumed. Make sure these activities are idle.
            // 获取到这个屏幕下的焦点RootTask
            final Task rootTask = display.getFocusedRootTask();
            // 重点* 2. 
            // 如果当前屏幕下没有 RootTask 有焦点 或者这个RootTask下面没有Activity (非常见场景)
            // 则也不需要处理
            if (rootTask == null || !rootTask.hasActivity()) {
                continue;
            }
            // 获取这个 Task下顶部处于 resumed 状态的 Activity
            final ActivityRecord resumedActivity = rootTask.getTopResumedActivity();
            // 有值，且不处于空闲状态
            if (resumedActivity == null || !resumedActivity.idle) {
                // 打印log
                ProtoLog.d(WM_DEBUG_STATES, "allResumedActivitiesIdle: rootTask=%d %s "
                        + "not idle", rootTask.getRootTaskId(), resumedActivity);
                // 重点* 3. 
                return false;
            }
        }
        // End power mode launch when idle.
        mService.endLaunchPowerMode(ActivityTaskManagerService.POWER_MODE_REASON_START_ACTIVITY);
        // 重点* 4. 
        return true;
    }

    4个重点，前面2个为 continue ，后面2个为 return。

      1. 屏幕如果处于休眠状态
      1. 这个屏幕下没有RootTask 有焦点， 或者有焦点但是下面没有 Activity

    这两种场景知道就好，不是常见场景，所以不用过多过滤

      1. 这里是第一个return， 那什么情况下会在这里返回 false 呢？

    首先不满足前面2个 continue 的条件，也就是：屏幕不处于休眠状态，且焦点 RootTask 下面有 Activity。

    然后满足下面2个条件之一都返回false。

    • 3.1 表示当前设备中没有处于 resumed 状态的 Activity （非正常场景）

    • 3.2 存在处于 resumed 状态的 Activity ，但是这个 Activity 不处于空闲状态

      1. 返回true，表示当前设备上要么没有处于 resumed 状态的 Activity，或者有，但对应的 Activity 都处于空闲状态

    满足以下任意条件都返回true。

    • 4.1 屏幕处于休眠状态
    • 4.2 没找到屏幕中有焦点的 RootTask
    • 4.3 屏幕不处于休眠，并且有焦点 RootTask ,并且这个 RootTask 下面有处于“Resumed状态的Activity”，但对应的 Activity 都处于空闲状态

    搞这么复杂，是因为代码的严谨性，所以考虑的因素很多。 但是我们分析主流程可以不考虑那么多。 以常见不锁屏操作的场景，屏幕上肯定至上有一个 可见的 Activity ，所以 resumedActivity 肯定不为null，那么返回的场景要么就是 3.2 返回 false，要么就是 4.3 返回 true。

    所以这个方法的意思就是： 返回当前设备上显示的 Activity 中，是不是都处于空闲状态。

    这个结论和它后面的执行是匹配的。 如果 RootWindowContainer::allResumedActivitiesIdle 返回true ， 说明当前处于空闲状态，则触发 ActivityTaskSupervisor::scheduleIdle 方法

    # ActivityTaskSupervisor

    final void scheduleIdle() {
        if (!mHandler.hasMessages(IDLE_NOW_MSG)) {
            if (DEBUG_IDLE) Slog.d(TAG_IDLE, "scheduleIdle: Callers=" + Debug.getCallers(8));
            // 发送 IDLE_NOW_MSG
            mHandler.sendEmptyMessage(IDLE_NOW_MSG);
        }
    }

    这个方法发送了一个 “IDLE_NOW_MSG ”消息，表示当前处于空闲状态，然后执行响应逻辑。

    然后会执行到 ActivityTaskSupervisor::activityIdleInternal ActivityTaskSupervisor::processStoppingAndFinishingActivities

    # 1.3 RootWindowContainer::allResumedActivitiesVisible

    # RootWindowContainer
    boolean allResumedActivitiesVisible() {
        // 可能作为返回值
        boolean[] foundResumed = {false};
        // 重点 * 1. 遍历所有的RootTask
        final boolean foundInvisibleResumedActivity = forAllRootTasks(rootTask -> {
            // 拿到 ResumedActivity
            final ActivityRecord r = rootTask.getTopResumedActivity();
            if (r != null) {
                if (!r.nowVisible) {
                    // 重点 * 2. 已经找到
                    return true;
                }
                // 重点 * 3. 如果ResumedActivity可见则对foundResumed处理
                foundResumed[0] = true;
            }
            // 重点 * 4. 继续遍历
            return false;
        });
        if (foundInvisibleResumedActivity) {
            // 重点 * 5. 当前手机存在是 resumed 但不可见的 Activity
            return false;
        }
        // 重点 * 6. 返回
        return foundResumed[0];
    }

    这里有很多 return ，前面2个是 forAllRootTasks 方法里的 return 。返回 true 则停止遍历，并且 forAllRootTasks 返回 true ，如果返回 false ，则继续遍历，最终 forAllRootTasks 返回 false 。 和当前 allResumedActivitiesVisible 整个方法的 return 是有区别的，这点需要注意。

    重点分析：

      1. 遍历屏幕的每个 RootTasks ，根据返回的变量可知是想找到一个是 resumed 但不可见的 Activity 。
      1. 如果执行到这里，那说明已经找到了是 resumed 但不可见的 Activity 。 这里 return true ，则会停止整个 forAllRootTasks ，并且 foundInvisibleResumedActivity = true ，最终 allResumedActivitiesVisible 方法返回值为 false。（对应重点5：找到不可见的 resumed Activity 时返回 false）
      1. 将 foundResumed 数组的第一个元素设为 true ，表示找到可见的 ResumedActivity ，如果后面遍历没有在重点2除返回，则最终在方法最后 return true 。（对应重点6.2）
      1. 如果执行到这里返回 false，则表示这个 RootTask 中没有找到是 resumed 但不可见的 Activity，所以会继续下面 RootTask 的遍历 。如果每次遍历都走这，则最终 foundInvisibleResumedActivity - false 如果后续的遍历一直是这样，则最终在方法最后 return false 。（对应重点6.1）
      1. 如果在这里返回 false，说明遍历的时候找到了是 resumed 但不可见的 Activity，也就是代码执行到了重点2处。
      1. 这里的返回有2个值，
      • 6.1 返回 false，说明没有执行到重点3处，也就说是整个屏幕的 RootTask 都没找到一个是 resumed 状态的 Activity 。
      • 6.2 返回 true，说明找到是 resumed 状态，且可见的 Activity 。（这种是正常状态，正常情况状态是 resumed 的 Activity 就应该是可见的）

    对这个方法的总结： 只有1种情况返回 true :

      1. 也是理想状态，说明处于 resumed 状态的 Activity 也处于可见状态。

    有2种情况返回 false ，说明 还需要 Framework 继续处理后续逻辑：

      1. 屏幕上有处于 resumed 状态的 Activity 但却不见， 后续肯定要触发使其可见，或者纠正其状态
      1. 整个屏幕都找不到一个处于resumed 状态的 Activity，那也是很不正常的

    如果这个方法返回true，则会发生一个 “PROCESS_STOPPING_AND_FINISHING_MSG” 消息，对应的处理是直接调用 ActivityTaskSupervisor::processStoppingAndFinishingActivities 来触发 Activity 的 onStop 或者 onDestroy 。

    # 2. ResumedActivity 相关

    # 2.1 什么是 ResumedActivity

    从字面意思理解，就是一个处于 Resumed 状态的 Activity。那什么是 Resumed 呢？ 执行完 resume 就是 resumed 呗。

    正常来说，想要显示一个 Activity ，从应用开发角度来说，生命周期需要执行到 onResume ，从framework角度，就是 resume 这个 Activity ，比如常见的 TaskFragment::resumeTopActivity 方法的命名也有点这个意思。

    在 framework 中对 ActivityRecord 定义了以下几个状态：

        }
        // 2. 拿到ResumedActivity
        final ActivityRecord taskResumedActivity = getResumedActivity();
        // 定义一个局部变量
        ActivityRecord topResumedActivity = null;
        // 3. 遍历孩子
        for (int i = mChildren.size() - 1; i >= 0; --i) {
            final WindowContainer child = mChildren.get(i);
            // 已经是 LeafTask，所以孩子里不会有Task
            if (child.asTaskFragment() != null) {
                // 3.1 调用TaskFragment::getTopResumedActivity
                topResumedActivity = child.asTaskFragment().getTopResumedActivity();
            } else if (taskResumedActivity != null
                    && child.asActivityRecord() == taskResumedActivity) {
                // 3.2 赋值
                topResumedActivity = taskResumedActivity;
            }
            if (topResumedActivity != null) {
                // 3.2 有值的话就返回
                return topResumedActivity;
            }
        }
        // 4. 啥也没有
        return null;
    }

    以“桌面冷启动应用”的场景，那 TargetActivity 所在的 Task 既是 RootTask，也是 LeafTask 。

      1. 如果不是叶子节点的 Task ，则从上往下遍历孩子 Task ，递归到结果就返回。其实最终还是会返回叶子节点最上面的 ResumedActivity

    当前分析的冷启动场景执行到 RootWindowContainer::allResumedActivitiesIdle ，所以肯定是 LeafTask

      1. 拿到当前 Task 的 ResumedActivity
      1. 然后开始遍历孩子，
      • 3.1 如果是 TaskFragment 则调用 TaskFragment::getTopResumedActivity (一般不会)
      • 3.2 如果遍历到孩子刚好是这个 Task 下的 ResumedActivity ，则赋值给 topResumedActivity ，用于下面返回

    其实这一步我有点迷糊，直接返回 getResumedActivity() 不就好了吗？ 后面想到这个方法的执行场景很多，根据当前分析的案例确实如此，但是有其他场景，就有不同的执行逻辑。 比如执行这个方法的的 Task 下面有多个 Task 和 ActivityRecord

      1. 没有符合条件的 Activity 就返回null
